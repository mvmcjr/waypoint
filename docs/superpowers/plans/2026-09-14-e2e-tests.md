# End-to-End UI Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local Windows end-to-end suite (21 tests) that drives the real Waypoint app, with its Tauri shell, Rust backend and real git, against freshly generated fixture repos. It asserts both the UI and the resulting git state.

**Architecture:**
- `tauri-driver` fronts `msedgedriver`, and `msedgedriver` drives the WebView2 of a debug build that uses a separate identity.
- Each test builds a fixture into a temp folder. It then starts its own WebDriver session with WebdriverIO's standalone `remote()` — seeding the app's recents store with the fixture folder rather than passing it as a command-line argument, since `tauri:options.args` never reaches the Tauri app process — performs the UI steps, asserts on the UI and via the git CLI, and ends the session.
- Mocha runs the specs. A small Node runner handles preflight, build-if-stale and the `tauri-driver` lifecycle.

**Tech Stack:** WebdriverIO (standalone `remote`), `tauri-driver`, `msedgedriver`, Mocha, tsx, Node `child_process` for git, Tauri 2 CLI.

**Spec:** `docs/superpowers/specs/2026-09-14-e2e-tests-design.md` (binding).

**Deliberate deviation from the spec (ruling):** the spec names a `wdio.conf.ts` test runner and `reloadSession`. This plan uses Mocha plus WebdriverIO's standalone `remote()` instead: `tauri:options.args` never reaches the app process, and the fixture path goes in through the app's seeded recents list, so every test needs its own session anyway. Mocha plus standalone `remote()` was kept over the WDIO test runner because it gives each test an explicit, independent session and full control over failure artifacts, without a `wdio.conf.ts` runner config. Everything else in the spec stands: one fresh app per test, isolation, artifacts and preflight. Layout consequence: `e2e/wdio.conf.ts` becomes `scripts/e2e/run.mjs` plus `e2e/support/*`.

## Global Constraints
- **Do NOT commit, stage, or create branches.** The work stays on the `feat/worktrees` working tree. The user requires `/code-review high` before any commit.
- **Windows only.** Keep OS-specific code inside `scripts/e2e/setup.mjs`, `scripts/e2e/run.mjs` and the capabilities object.
- **The test build uses identifier `com.waypoint.e2e`** (`src-tauri/tauri.e2e.conf.json`) and builds into `src-tauri/target/e2e` via `CARGO_TARGET_DIR`, so it never overwrites the dev build or touches the user's app data.
- **The Explorer prompt is suppressed** by seeding `%APPDATA%\com.waypoint.e2e\waypoint.json` with `{"context_menu_asked": true}` before each launch. The key comes from `src/App.tsx:77`.
- **Every test uses a fresh fixture** in `%TEMP%\waypoint-e2e\<runId>\<slug>\`. The folder is deleted when the test passes and kept when it fails; the failure prints its path.
- **Every test asserts both** the UI and the real git state.
- **No `pause`/`sleep`.** Use `waitForDisplayed`, `waitUntil`, and the `waitForGit` helper (10 s default).
- **Selector priority:**
  1. Accessible name (`aria/<name>`).
  2. Visible text inside a known container.
  3. `data-testid`, added to product code only when 1 and 2 are unstable. Every testid must be listed in `e2e/README.md`.
  4. Never Tailwind classes.
- **Tests run serially.** One app at a time.
- **Failure artifacts** go to `e2e/artifacts/<spec>/<test>/`: `screenshot.png` and `dom.html`.
- **Unit suites stay green:** `pnpm test run`, `pnpm exec tsc --noEmit`, and `cd src-tauri && cargo test`. Vitest must exclude `e2e/**`.
- **Selectors must be confirmed against the live DOM.** When a selector in this plan doesn't match, inspect with `await app.getPageSource()`, adjust the selector, and keep the test's intent and git assertions. Record every such adjustment in the task report.
